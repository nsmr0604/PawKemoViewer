# ドメインモデルの境界

## M4.1 — モデルマッピングの棚卸し

| 機能 | 通信/入力 | 永続化 | アプリケーションと表示 |
|---|---|---|---|
| クリエイター索引 | `GET /creators` の `CreatorIndexDto` | `toCreatorIndexRows` が `CreatorRow` を構築する。`db.ts` がパックをエンコード/デコードし、レガシーの行ごとのレコードも読める。 | クリエイターのユースケースは検索行と、そこから導出した直接投稿リンクを返す。`CreatorsPage` が表示順と表示する結果を選ぶ。別個のプロフィールエンドポイントは引き続き `PawCreator` を返す。 |
| 投稿詳細 | ハッシュルートが service、クリエイター ID、投稿 ID を渡す。API のレスポンスは `src/types.ts` で宣言された `PawPost`、`PawRevision`、`PawComment` を使う。 | リクエストキャッシュと、セッションストレージのナビゲーション記録。投稿本文はこのスライスでは永続化しない。 | 詳細のユースケースは識別子を検証し、投稿と順序付けしたリビジョンを結合し、リビジョンの別個の失敗を保持する。コメントは投稿の後に続く。画面が表示するリビジョンを選び、メディアの表示を構成する。 |
| ホームとクリエイターの投稿 | リストのエンドポイントからの `PawPost[]`。 | リクエストキャッシュ。 | ページングのユースケースは行と完了状態を返す。追記、フィルタリング、スクロールは React が所有する。 |
| ロケール | プラットフォームのロケール一覧と、選択された JSON ファイル。 | ロケールリポジトリ背後のプライベート/共有ファイル。 | 取り込みの結果は型付きである。i18n が辞書を検証して重ね、設定が UI のメッセージと有効な言語を所有する。 |
| お気に入りとバックアップ | アカウントのお気に入りのレスポンス、または取り込んだバックアップ JSON。 | ローカルのフォロー/設定のミラーと IndexedDB の `SeenEntry`。バックアップは明示的な形式/バージョンを持つ。 | Favorites 画面が UI の状態を組み立てる。取り込みの検証とストレージの順序は `backup.ts` にある。 |

最初のドメインルールは、詳細の読み込みとリビジョン API が使う投稿識別子の妥当性である。両者のルールは同一である。ハッシュの解析もルートの形を検査し、意図的に既存の構文のみの受け入れを維持する。ワイヤのレコード、DB のコーデック、表示状態は、現在の所有者に残す。

## M4.2–M4.3 — ルールの配置と失敗

- 投稿識別子の述語は純粋である。両方の識別子と対応する service を検査する。有効な値の trim、デコード、書き換えは行わない。ルーティングとトランスポートは、既存の契約が必要とする箇所でのみエンコード/デコードする。
- 複数のエントリーポイントが同じ業務ルールを共有する場合、想定される検証失敗は型付きのドメインエラーを使える。`InvalidPostContextError` は安定したコード `invalid-post-context` を公開する。呼び出し側は既存の表示用または診断用のメッセージを渡し、拒否するかログするかを決める。不正なリビジョン入力では、検証はリクエストスケジューラより前に実行される。
- HTTP ステータスとリビジョンの 404 の解釈は、トランスポート/アプリケーションの境界に置く。IndexedDB、ロケールの解析、キャッシュ、翻訳、描画はドメインの外に置く。複数の呼び出し側が同じポリシーを必要とするとき、または別々にテストすることでリスクが下がるときに、純粋なルールを追加する。エラークラスは、呼び出し側が特定の区別可能な条件を共有する場合にのみ正当化される。

## M4.4 — 依存の分離

`npm run test:domain` は Node で投稿識別子のルールを実行し、`src/domain` のすべての TypeScript ファイルを、ES2022 のライブラリ型を使い、自動のアンビエントパッケージを無効にしたプログラムで型チェックする。テストは、型のみの依存を含め、ドメインまたは TypeScript 標準ライブラリの外にある解決済みソースをすべて拒否する。React、Tauri、DOM、IndexedDB、ネットワーク API は、ドメイン境界の外である。アプリケーションの残りに対する広範な依存ルールは、M7 の一部として残る。
