# 作業・引き継ぎ手順

## 作業前

1. `AGENTS.md`、[開発状況](../STATUS.md)、関連する設計資料を読む
2. 対象ブランチと最新コミット・PR を確認し、重複作業がないか照合する
3. 依存タスクの完了を確認し、着手可能な未完了項目を一つ選ぶ
4. 変更範囲とリスクを見直し、必要に応じて作業を分ける

## 作業中

- 選んだ作業とその前提の修正に絞り、既存の動作とセキュリティ上の制約を守る
- 1 コミットにつき 1 作業を目安とする。最小限の関連テストから実行し、
  広い範囲の検証は節目でまとめる
- 実行できなかった検証とその理由を明記する。設計・棚卸しの資料はコードと照合する
- 複数エージェントで並行する場合は、変更ファイルと契約の依存関係が重ならない作業を選ぶ

## 中断・完了時の引き継ぎ

**引き継ぎ、作業状況、検証結果、エージェントへの申し送りは日本語で記述する。**
コマンド、パス、識別子、エラーの原文は必要に応じてそのまま引用する。

[開発状況](../STATUS.md) に、作業内容、コミットや PR、変更ファイル、検証コマンドと結果、
未解決事項、次に着手できる作業を記録する。設計資料を加えた場合は
[設計資料の目次](README.md) からリンクする。

共有する引き継ぎは Git 管理下の `docs/` に置く。`notes/` はローカル用とする。
