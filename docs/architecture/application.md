# レイヤーと起動時の構成

## 起動の流れ

```text
index.html
  → src/main.tsx の bootstrap()
  → PlatformRuntime を初期化
  → アプリケーションのユースケースとリポジトリを組み立て
  → 設定ストレージを初期化
  → HTTP User-Agent を適用
  → 外部言語を再走査し、保存された表示言語を読み込み
  → React をマウント
  → App / router が画面を表示
```

Tauri 版では `src-tauri/src/main.rs` が `pawkemoviewer_lib::run()` を呼び出し、Rust 側が Tauri コマンド、ログ、pkv メディアプロトコル、モバイルプラグインを登録します。

## 層の責務

| 層 | 場所 | 責務 | 依存してよい相手 |
|---|---|---|---|
| Domain | `src/domain/` | React・Tauri・DOM に依存しない純粋ルール。投稿識別子、元記事 URL、Referer 導出など | 同層と TypeScript 標準ライブラリ |
| Application | `src/application/` | ユースケース、入力・結果の型、部分成功、協調的なキャンセル | Domain、共有モデル |
| Infrastructure | `src/infrastructure/` | API と保存先をアプリケーションの契約へ接続 | Application、Domain、既存の API / 保存ヘルパー |
| Platform | `src/platform/` | 実行環境の検出、ストレージ、ファイル、ログ、ライフサイクルなどのアダプター | Tauri API、Web API、Application / Infrastructure には依存しない |
| Presentation | `src/components/` / `src/pages/` / `src/App.tsx` | 画面状態、ナビゲーション、描画、確認ダイアログ、操作の通知 | Composition Root、Platform 契約、共有 UI |
| Composition Root | `src/` の起動・配線コード | ユースケースへ現在の API、リポジトリ、Platform サービスを注入 | 各層の実装 |

`npm run check:boundaries` が静的インポート、再エクスポート、`import type`、リテラルで書かれた動的インポートを検査します。計算されたモジュールパスや実行時の効果までは検査しません。

## 主要な処理の流れ

### ホームとクリエイター投稿

1. 画面が検索語、サービス、タグ、オフセットをアプリケーションの入力へ渡します。
2. ユースケースが API を呼び出し、短いページを終端として扱います。
3. 画面がページの追記、フィルター、スクロール、再試行、古い応答の破棄を担当します。
4. API のスケジューラと GET キャッシュは `src/api.ts` に集約し、リポジトリ側で重複実装しません。

### クリエイター索引

- `GET /creators` の DTO を索引行へ変換し、IndexedDB のパック形式で保存します。
- 検索はキャッシュ済み索引を優先し、必要時に更新します。
- 更新処理は AbortSignal で協調的にキャンセルし、キャンセル後に新しい書き込みを始めません。
- プロフィール、タグ、告知、投稿一覧は別の API 呼び出しです。

### 投稿詳細

1. ルートの `service` / `creatorId` / `postId` を Domain で検証します。
2. 投稿詳細を取得し、その後で改訂履歴を整列します。
3. 改訂履歴の 404 は「改訂なし」、その他の失敗は投稿とは別のエラーとして保持します。
4. コメントは投稿の読み込み後に別途取得します。
5. 画面が版の選択、メディア、お気に入り、フラグ、前後移動を担当します。

### 言語ファイル

- ファイル名の言語コード、UTF-8、サイズ、JSON、キーと差し込み変数を検証します。
- アプリ専用領域と追加フォルダーの書き込み先を区別します。
- 複数ファイルの取り込みは、ファイルごとの成功・失敗をまとめて返します。
- 削除確認、メッセージ表示、言語の再適用は画面側に残します。

### バックアップとフォロー

- pawchive アカウントをフォローの正とし、ローカルはミラーとして扱います。
- バックアップは設定、フォロー、既読を検証してから復元します。
- 復元先のストレージが利用できない場合は、IndexedDB の既読を変更する前に失敗します。

## エラーとキャンセルの規約

- 想定された空結果は成功として返します（改訂なし、コメントなし、終端ページなど）。
- 運用上で意味のある失敗は型付き結果または元のエラーで返します。
- `AbortSignal` は次の取得・書き込みを止める協調的なキャンセルです。送信済み HTTP や開始済みファイル書き込みを強制停止しません。
- `unknown` / `any` を JSX の子にせず、明示的に boolean 化してから描画します。
